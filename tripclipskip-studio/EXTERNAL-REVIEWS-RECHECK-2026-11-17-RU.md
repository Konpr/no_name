## 2. Вопрос `[6,3,9,0]`: что доказано, а что нет

`PhaseSchedule.phase_index(step, total)` использует `step >= ceil(total × start)`. Для `total=20` и последовательных наблюдаемых шагов `0..17`:

| Границы P1/P2/P3/P4 | Плановые пороги | Счётчики при 18 вызовах |
|---|---|---|
| `0 / .30 / .45 / .90` | `0, 6, 9, 18` | **`[6,3,9,0]`** |
| `0 / .25 / .50 / .75` | `0, 5, 10, 15` | **`[5,5,5,3]`** |

Первый сценарий уже воспроизведён локальным тестом `test_legacy_6_3_9_0_explained_by_unreached_boundary`. **Однако он не доказывает, что на GPU были именно границы `.30/.45/.90` и шаги `0..17`.** В разговоре пользователь подтвердил, что менял Phase 2 вручную. Для первичного старого лога по-прежнему отсутствует полная синхронная трасса.

У z.ai верно описана **условная причина**: если фазовый порог не достигается, conditioning от P4 не используется и финальные вызовы идут с P3. Это реальная проблема ожидаемой семантики. Но утверждать **доказанную причину конкретного GPU-события** без фактических `starts/step/total` преждевременно. Исправлять пороги вслепую нельзя.

**И ещё важно:** опциональная политика «гарантировать последние N вызовов как P4» принципиально не гарантируема в онлайн-цикле без знания числа будущих вызовов; нельзя обещать pre-generation warning как достоверное предсказание неполного числа forwards. Можно исследовать sigma, sampler-step или определённый offline count и явно прописать семантику.

## 3. Ревью идей по степени достоверности

| Предложение / критика | Вердикт по исходникам | Следующее действие |
|---|---|---|
| Claude: passive `(step,total,sigma)` trace | **Хорошее и осуществимое**: `CFGDenoiser.forward(self, x, sigma, uncond, cond, ...)` действительно принимает sigma | P0: opt-in запись скаляров (без содержимого промпта, без хранения тензоров); сравнение нескольких самплеров |
| Claude: sigma как третий источник прогресса | **Перспективный эксперимент**, но не универсально монотонен (возможен churn и разные шкалы sigma) | Сначала только trace; после GPU тестов — документированная модель нормализации и opt-in |
| Claude/Grok: fallback на P1 при ошибке `setup_conds` | **Обоснованная политика**, текущий путь при ошибке повторной подготовки делает `raise`, внешний `process` выключает расширение | Сделать откат только при сохранённой исходной фазе и полном восстановлении состояния; при неполном rollback — abort, не скрытая деградация |
| Gemini: `XYZ Plot` и Multi-Phase | **Подтверждённый конфликт:** `xyz.__set_value()` включает `args[idx+5]`, но не очищает `args[idx+13]`; `multi_count>0` имеет приоритет | P0.4: сбрасывать multi при выборе legacy осей или разделить оси; интеграционный тест |
| Gemini: `cache.invalidate` ломает новые вложенные кэши | **Не относится к текущему `modules (4).zip` напрямую**: `cached_c/cached_uc = [None,None]`, штатный `get_conds_with_caching` обращается к `[0]` как ключу | Не вносить необоснованную правку; отдельно добавить поддержку обнаруженного многослотового формата и тест, если он реально встретится |
| Gemini: повторные `setup_conds` имеют side effects | **Подтверждённый архитектурный риск**: настоящая custom `setup_conds()` очищает/настраивает REGION, парсит TONEG, меняет `region_data` | P0: тесты cleanup/rollback; P2: изолированный conditioning builder только после подтверждения эквивалентности |
| z.ai: PhaseTrace per-image | **Обоснованное предупреждение**, но нужно различить `batch_size>1` (один проход на много картинок) и `n_iter>1` (повторные проходы) | P0: в trace явно указать единицу учёта и сделать тесты каждого сценария; не объявлять job-counters индивидуальными автоматически |
| z.ai: «24 позиционных аргумента» | **Уязвимость сопровождения**, но не доказанный текущий runtime-баг: `ScriptRunner` настоящей сборки действительно передаёт `*script_args` | Сделать единый контракт параметров и интеграционный тест, а не просто заменить сигнатуру на `*args` |
| z.ai: `model/custom`, `l=1.0` не native | **Слишком широкое утверждение:** `a1111 + 1.0` намеренно идёт через native path; `custom` по определению может отличаться от выключенного TCS | Тестировать точное совпадение с *выбранным reference*, включая `last_hidden_state`/LayerNorm, и отдельно native-equivalence для `a1111` |
| z.ai: `conditioning_signature` и циклы | **Пограничный риск**: глубина ограничена 8, не произвольная рекурсия; циклические контейнеры приведут к явной ошибке | Не расширять рекурсию без тестов и схемы объектов; fail-closed на неизвестной структуре |
| z.ai: `MethodPatch.remove` оставляет closure | **Осознанный компромисс:** метод не перезаписывает более новый сторонний patch, что безопаснее его безусловного снятия | Диагностировать вложенные wrapper-цепочки и проверить reload; нельзя просто возвращать original поверх чужого patch |
| z.ai: `from modules import shared` внутри init | **Необоснованный диагноз поломки**, обычный lazy import; сейчас ничего не доказывает | Не считать багом без runtime-воспроизведения |
| z.ai: атомарная запись пресетов уже есть | **Подтверждено:** `config.save_preset()` делает `flush`, `os.fsync`, `os.replace` | Отметить реализованным; отдельно проверить сбои записи и схемы миграции |
| Grok: GPU native-equivalence + hook lifecycle | **Принимается полностью как P0** | Точное сравнение `TCS off/on` в SD1.5 и SDXL, interrupt/reload/checkpoint/REGION/Hires |

## 4. Что изменено в плане после ревизии

1. **P0.1:** passive trace с `sigma`, раздельные predicted и observed счётчики, явное различение арифметического примера и доказательств GPU; никакого «clamp в последние N вызовов» без обоснованного источника прогресса.
2. **P0.3:** политика безопасного rollback при ошибке подготовки фаз, кэш-контракт, отличие `batch_size` от `n_iter`, тесты вложенных хуков.
3. **P0.4:** отдельный короткий блок подтверждённого конфликта XYZ, соответствия `ui/script_args`, версии схемы конфигурации, выбора reference.
4. **P1:** существующая атомарная запись пресетов отмечена `[x]`, оставлены отдельные задачи на миграцию и импорт.
5. **P2/P3:** расширенные функции сохраняются в плане как отложенные, без обещаний прироста качества и без ускоренного релиза до GPU-проверки P0.

## 5. Рекомендуемая ближайшая последовательность

1. **GPU: один эталонный Euler 20/4** в версии 0.3.4 с полностью одинаковыми настройками для `denoiser` и `sampler`; получить синхронные параметры PNG Info и Phase Trace.
2. **Native-equivalence** для TCS=1.0 при reference=`a1111` и разных значениях штатного Clip Skip, затем отдельный случай TCS=2.5; сравнивать тензоры/детерминизм, не только визуальное сходство.
3. **Исправить подтверждённый конфликт XYZ** (узкое изменение с регрессионным тестом), затем сделать пассивный trace; приоритет остальных UI-функций ниже.
4. **Проверить negative/pooled/REGION, Hires, Interrupt, exception, batch/iteration** и выбрать строгую политику rollback.
5. После P0 развивать read-only Layer Map + Token Inspector, затем opt-in Absolute Layer Timeline и Composer.

**Итог:** сильные отзывы заслуживают учёта, но критический недочёт технического ревью — смешение *условно воспроизводимой арифметики* и *доказанной причины конкретного GPU-запуска*. Исправленный план не делает этой ошибки.
